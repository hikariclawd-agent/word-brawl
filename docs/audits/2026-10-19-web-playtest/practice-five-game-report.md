## Confirmed bug

### PRACTICE-01 — Start Practice creates a Private Brawl session

- **Severity:** High; blocks the entire Practice mode and creates unintended online session state.
- **Confidence:** Confirmed in one fresh isolated browser context with direct network evidence.
- **Expected:** Practice should initialise a local CPU game, show the local Practice round, and create no online room or Private Brawl lobby.
- **Actual:** The app navigated to a screen headed `PRIVATE BRAWL`, displayed a six-character session code, showed `YOU HOST`, `Invite players`, `Waiting for 1 more player`, and `Close Session`, and filled the room with two CPU seats. It issued a `POST /rest/v1/rpc/create_managed_room` request.
- **Observed disposable session:** code `CXA8D6`; room identifier `08794bdc-6c8f-4ba0-abda-d6dc8321ba69`.
- **Reproduction:** `Start Playing` → `Play as Anonymous` → `Practice` → `Start Practice`.
- **Evidence:** [practice-routing-blocked.png](./practice-five-game-evidence/practice-routing-blocked.png)
- **Classification:** Confirmed functional/routing defect, not a cosmetic issue and not a Playwright artefact.

The prior Practice finding documented that the menu item opened Private Brawl. In this run the menu item correctly opened the Practice setup screen, but `Start Practice` still entered Private Brawl. The advertised Practice mode therefore remains unavailable through the complete normal player journey.

## Timeout diagnosis

The earlier temporary runner waited for exact text `Answer fast` immediately after clicking `Finish Round`. The four dispute screenshots show that `Answer fast` is the round-entry heading, not a stable post-round transition marker. After `Finish Round`, the app renders an intermediate leaderboard headed `SESSION RESULT`, with `Choose Next Letter`, `Quit Game`, and the next-letter picker (`Random`, `Start Round`). The old wait therefore timed out while the app was in a valid intermediate state. This was a harness limitation, not evidence of an application freeze.

The revised temporary harness used rendered-state predicates:

- answer state: visible `Every answer starts with <letter>` and `Submit Answers`;
- intermediate state: visible `SESSION RESULT` and `Choose Next Letter`;
- final state: visible `GAME OVER`/final-result text.

It then used the visible `Choose Next Letter` → `Random` → `Start Round` controls before waiting for the next answer state. No force-clicks, DOM changes, internal functions, API shortcuts or database operations were used.
